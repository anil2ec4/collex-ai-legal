## 2. Şema (as implemented)

Hepsi `app_private` altında, hepsi `tenant_id uuid not null`, hepsinde RLS
açık ve tek `for all` politikası (`tenant_id = (select
app_private.current_tenant_id())`); `matter_items` ek olarak SAHİBİ DOSYA
üzerinden çözülür (ADR-011) ve `with check` kiracı eşitliğini de ister.

| Tablo | Anahtar | Sütunlar |
|---|---|---|
| `matters` | `id uuid` | `title` (1..300), `client`, `opposing`, `court`, `docket_no`, `kind` ∈ dava/danismanlik/sozlesme/icra/diger, `status` ∈ acik/beklemede/kapali, `notes`, `created_at`, `updated_at` |
| `matter_items` | `item_id uuid` | `matter_id` (FK cascade), `kind` ∈ file/answer/draft/note/event/deadline, `ref_id text null`, `payload jsonb`, `created_at`, `updated_at` |
| `answers` | `run_id text` | `matter_id` (FK **set null**), `question`, `status`, `mode` ∈ local/live, `finalizable`, `evidence_count`, `as_of date`, `result jsonb`, `bundle jsonb` (metinler DAHİL), `created_at`, `updated_at` |
| `drafts` | `(draft_id text, version_no int)` | `matter_id` (FK set null), `kind`, `template`, `title`, `unsupported_count`, `body jsonb`, `created_at` |
| `settings` | `(tenant_id, key)` | `value jsonb`, `updated_at` |

İndeksler: `matters(tenant_id, created_at desc)`, `matters(tenant_id,
status)`, `matter_items(tenant_id, matter_id, created_at desc)`,
`matter_items(matter_id, kind)`, kısmi `matter_items(tenant_id,
(payload->>'dueDate')) where kind='deadline'`, `answers(tenant_id,
created_at desc)`, `answers(matter_id)`, `drafts(tenant_id, created_at
desc)`, `drafts(matter_id)`. `drafts(draft_id, version_no desc)` için ayrı
indeks yok: PK geriye taranıyor.

**Ledger tablosu migration'da değil, ledger kodunda yaratılır** (boş bir
ledger, ledger-öncesi DB'yi "hiçbir şey uygulanmamış" gibi gösterirdi).

## 3. Migration ledger (ingestion/migrations.py)

```
LEDGER_TABLE = "app_private.schema_migrations"   (filename pk, applied_at)
LEDGER_BOOTSTRAP_BOUNDARY = "20260827120000"
LEDGER_SENTINEL_MARKER = "[LEDGER SENTINEL]"     -- "-- [LEDGER SENTINEL] app_private.settings"
apply_missing_migrations(conn, directory=None) -> MigrationReport
    .bootstrapped / .applied / .already_applied  (to_json_dict())
ledger_state(conn) -> LedgerState(exists, applied, has_documents, needs_bootstrap)
ensure_ledger(conn); migration_timestamp(path); ledger_sentinel(path)
```

Kural: ledger yok/boş **ve** `legal.documents` varsa bootstrap — zaman damgası
≤ sınır olan her çalıştırılabilir migration uygulanmış sayılır; sınırdan
YENİ bir migration yalnız başlığındaki sentinel relation mevcutsa uygulanmış
sayılır (psql ile yüklenmiş DB'ler), yoksa uygulanır. Her migration kendi
ledger satırıyla **tek transaction** içinde koşar (migration dosyalarında
transaction kontrolü yok — doğrulandı). Sınırdan yeni her migration bir
sentinel taşımak ZORUNDA (`test_bootstrap_boundary_is_a_real_migration_and_newer_ones_declare_sentinels`).

`intake.cli --ensure-db` çıktısı (additive):
`{"ensureDb":{"database","created","migrationsApplied":[...],"migrationsBootstrapped":[...],"migrationsAlreadyApplied":n}}`.

Sözleşme [X]: `with_connect_timeout(dsn)` DSN'e `connect_timeout=5` ekler
(varsa korur) ve bu DSN `intake.ingest` / `ingestion.pipeline` içindeki her
`psycopg.connect`'e gider. `psycopg.OperationalError` →
`{"error":{"kind":"STORE_UNAVAILABLE","message":"Yerel veritabanına ulaşılamadı."}}`,
exit 2; sürücü metni asla basılmaz.

## 4. TS sözleşmeleri (as implemented)

### `control-plane/src/api/answerService.ts`
```ts
export type AnswerMode = "local" | "live";
export interface StoredAnswer { runId; result; bundle; storedAt; mode?: AnswerMode; question?: string; matterId?: string | null }
export interface AnswerSummary { runId; question; status; mode; matterId: string|null; createdAt; evidenceCount; finalizable }
export interface AnswerStore { put(e): void; get(runId): StoredAnswer|undefined; warm?(runId): Promise<void>;
  list?(opts?: { matterId?; limit? }): Promise<AnswerSummary[]>; attach?(runId, matterId: string|null): Promise<void> }
export function summarizeStoredAnswer(entry): AnswerSummary
export function clampListLimit(limit?, fallback = 50): number      // 1..200
export class InMemoryAnswerStore implements AnswerStore              // warm no-op, list cache (yeniden-yeni), attach cache
```
`put()` `matterId` vermezse önbellekteki dosyalama korunur; açık `null`
ayırır.

### `control-plane/src/store/answerStore.ts`
```ts
export const LOCAL_TENANT_ID = "00000000-0000-0000-0000-000000000001";  // yeniden tanımlı, import edilmez
export class PgAnswerStore implements AnswerStore {
  constructor({ sql: Sql; tenantId?; capacity?; log?: (line) => void })
  put(entry): void          // önbellek + arka plan upsert; hata: stderr "[collex] ANSWER_PERSIST_FAILED runId=…: <code>: <mesaj>"
  get(runId)                // yalnız önbellek
  warm(runId)               // DB → önbellek
  list({ matterId?, limit? })
  attach(runId, matterId|null)   // önce flush(), sonra update + önbellek

}

```

### `control-plane/src/store/draftStore.ts`

## 5. Entegrasyon adımları (entegrasyon hattı uygular)

`control-plane/src/api/server.ts`
1. `ApiDependencies.answerStore?: AnswerStore` (`InMemoryAnswerStore` yerine; import `type AnswerStore` from `./answerService.js`). `createApp` içindeki varsayılan `new InMemoryAnswerStore()` aynen kalır.
2. `POST /v1/answer` ve `POST /v1/evidence-bundle` `answerStore.put({...})` çağrılarına `mode: "local", question: parsed.data.question` ekle.
3. `GET /v1/answers/:runId` ve `GET /v1/answers/:runId/evidence-bundle` async olsun; `get` öncesinde `await answerStore.warm?.(runId)`.
4. Yeni rota `GET /v1/answers?matterId=&limit=` → `{ answers: await answerStore.list?.({ matterId, limit }) ?? [] }` (`limit` `clampListLimit` ile; `list` yoksa `[]`).
5. `ApiDependencies` ek alanlar: `matterStore?: MatterStore`, `settingsStore?: SettingsStore`, `sql?: Sql` (health için). Mount: `app.route("/", createMattersRouter({ store: deps.matterStore ?? new InMemoryMatterStore(now), answers: answerStore, drafts: draftStore /* list varsa */, now }))` ve `app.route("/", createSettingsRouter({ store: deps.settingsStore ?? new InMemorySettingsStore() }))`. Drafting router'a `answers: answerStore` zaten gidiyor; C hattı `warm` çağrısını kendi rotalarında yapar.
6. `/v1/health` (sözleşme [H]): `const dbHealth = deps.sql ? await checkDatabase(deps.sql) : { db: "down" as const }` → cevaba `db: dbHealth.db, dbName: dbHealth.dbName, migrations: dbHealth.migrations` (+ `mcp`, `ai`, `demoCorpus` diğer hatlardan). Cevabın mevcut alanları değişmez.

`control-plane/scripts/serve.mjs`
```js
const { checkDatabase, describeDatabaseHealth } = await importControlPlane("src/store/health.ts");
const { PgAnswerStore } = await importControlPlane("src/store/answerStore.ts");
const { PgDraftStore } = await importControlPlane("src/store/draftStore.ts");
const { PgMatterStore } = await importControlPlane("src/matters/store.ts");
const { PgSettingsStore } = await importControlPlane("src/settings/store.ts");
const sql = createDb({ url: args.dsn });
const dbHealth = await checkDatabase(sql);                 // ≤ 3 s
console.log(`[collex] db     : ${describeDatabaseHealth(dbHealth)}`);
const app = createApp({ ..., sql,
  answerStore: new PgAnswerStore({ sql }), draftStore: new PgDraftStore({ sql }),
  matterStore: new PgMatterStore({ sql }), settingsStore: new PgSettingsStore({ sql }) });
```
`db: 'down'` iken sunucu yine kalkar (kayıtlar bellek içi çalışır, rotalar
503 `STORE_UNAVAILABLE` döner); `missing` iken banner `--ensure-db`
komutunu yazdırır. Kapanışta `sql.end` öncesi `await answerStore.flush?.()`.

`control-plane/src/api/openapi.yaml`: `/v1/matters`, `/v1/matters/deadlines`,
`/v1/matters/{id}`, `/v1/matters/{id}/items`, `/v1/matters/{id}/items/{itemId}`,
`/v1/settings`, `/v1/answers` (GET liste) yolları; `AnswerSummary`,
`Matter`, `MatterSummary`, `MatterItem`, `Settings` şemaları; `/v1/health`
cevabına `db`, `dbName`, `migrations`.

`control-plane/src/files/routes.ts` (F hattı): `STATUS_BY_KIND` tablosuna
`STORE_UNAVAILABLE: 503` (CLI artık bu türü exit 2 ile basıyor).

`control-plane/public/console.html` (UI hattı): sözlük kodları
`MATTER_NOT_FOUND`, `ITEM_NOT_FOUND`, `STORE_UNAVAILABLE`; tarihler
GG.AA.YYYY olarak çizilir (API ISO taşır).

## 7. Bilinen boşluklar / kararlar

- `PgAnswerStore.put` arka planda yazar: süreç yazma bitmeden ölürse o cevap
  DB'ye ulaşmaz (stderr'e `ANSWER_PERSIST_FAILED` düşmez, süreç yoktur).
  Kapanışta `flush()` çağrılmalı (entegrasyon adımı).
- `PgMatterStore.list` iki sorgu (dosyalar + `= any(ids)` kayıtlar) ve JS
  türetimi; solo avukat hacmi için uygun, binlerce dosyada SQL toplama
  gerekir.
- `GET /v1/matters/deadlines` kapalı (`kapali`) dosyaların açık sürelerini
  de listeler (sözleşme "open only" süre durumuna göre yorumlandı).
- RLS politikaları yerelde owner bağlantısıyla **bypass** edilir (belgelenmiş
  tek-kullanıcı duruşu); politikalar `db_local_check` c14'te probe rolüyle
  kanıtlandı, uygulama yolunda değil.
- Ledger yalnız `intake.cli --ensure-db` yolunda kullanılır;
  `ingestion.cli --apply-migrations`, `db_local_check`, demo ve test
  harness'leri ledger'sız yükler (bootstrap+sentinel bunu tanır).
- `control-plane/src/store/migrate.ts` yazılmadı (yukarıda).
- Bu hat konsola/server.ts'e dokunmadı; uçtan uca HTTP kanıtı entegrasyon
  sonrasına kalır.
