## 1. What was built

### Python intake / ingestion

| Item | File | What changed |
|---|---|---|
| Bounded connects | `ingestion/pipeline.py` | `connect_local(dsn, **kw)` — the ONE helper every local connection goes through; applies `connect_timeout=5` (`CONNECT_TIMEOUT_S`) unless the DSN or the caller already carries one. DSN string handed to psycopg verbatim. `DocumentOutcome.error_type` (additive) records the exception class behind a failed document. |
| Typed store failure | `intake/errors.py`, `intake/ingest.py` | `StoreUnavailableError` (kind `STORE_UNAVAILABLE`, http 503, FIXED message `Yerel veritabanına ulaşılamadı.`). `intake/ingest.py` wraps every DB touch in `_store_guard()` (psycopg `OperationalError` → the typed error, driver text withheld) and maps a mid-ingest `OperationalError` outcome the same way. The existing CLI `except IntakeError` therefore prints `{"error":{"kind":"STORE_UNAVAILABLE","message":"Yerel veritabanına ulaşılamadı."}}` and exits 2 — contract [X] — measured well under 10 s against a closed loopback port. |
| Per-page PDF statistics | `intake/extract.py` | `PageStats {page_count, pages_with_text, empty_pages}` (1-based), attached to `ExtractionOutcome.page_stats`. Gate is now PER PAGE: no page with a text layer → fail-closed `EXTRACTION_FAILED` with the existing message/warning (`taranmış PDF — OCR bu modda devre dışı`); a MIXED PDF ingests the text pages and warns twice: machine code `SCANNED_PAGES:<n>` + Turkish sentence naming the pages (`9 / 10 sayfada metin katmanı yok (taranmış olabilir): sayfa 2, 3, … — bu sayfalar dizine alınmadı; OCR bu modda devre dışı`, list bounded to 15 numbers). |
| Wire fields | `intake/ingest.py` | IntakeResult JSON gains `action: "created" \| "already-existed"` (+ `message: "Bu belge zaten yüklüydü"` for the latter) and `pages: {pageCount, pagesWithText, emptyPages}` for PDFs. `page_stats` is persisted under `metadata.fixture_meta.upload.page_stats`; `--show` returns it as `pages`. `--list` uses one grouped count join. |
| Upload cap | `intake/quarantine.py` | `UPLOAD_CAP_MIB = 25` is the single source; `MAX_FILE_BYTES = UPLOAD_CAP_MIB * 1024 * 1024`. **Kept at 25 MB**, reason in the file: the ZIP gates would stay safe at 100 MB, but the upload is one synchronous intake process with a 180 s budget and no progress channel; pypdf runs ~50-100 ms/page, so a 100 MB born-digital PDF would turn an up-front rejection into a 3-minute hang + 504. |
| Batched indexer | `ingestion/indexer.py` | `insert_chunks` sends rows in `executemany` batches of 500 (`INSERT_BATCH_SIZE`); same statement, same parameter tuple (`chunk_row`), same ordinal conflict arbiter, same transaction, same return value (psycopg 3 cumulative rowcount → conflicts not counted). Streaming/atomicity contract kept. |
| Reference analysis | `intake/analysis.py` | THE real 30k-paragraph bottleneck was not SQL: `legal_reference.parser.parse_references` is quadratic in the number of references (111 s for one 3.6 M-char call). `extract_references` now parses per blank-line block (overlong blocks cut at real sentence ends — never after `m.`, `E.`, `9.`) and re-bases spans; results are identical to a whole-text parse (asserted). 30k paragraphs: 3.6 s. |
| MCP child hygiene | `mcp_server_main.py` | `import os`; `load_dotenv` skipped when `COLLEX_NO_DOTENV=1`; root/console log level from `LOG_LEVEL` (standard names, unknown → INFO). Nothing else touched; tool surface unchanged (smoke: 54). |

Measured (30 000 paragraphs, 3.6 M code points, through `process_file`):
before 122.3 s (111 s in reference analysis, ~1 INSERT per chunk) → after
~16 s total (references 3.6 s, batched insert 8.4 s); the pytest gate
requires < 60 s.

### Launcher and scripts (`control-plane/scripts/`, repo root)

`serve.mjs` — order is now: (1) DB check with 3 s timeouts (`select 1`,
`to_regclass('legal.documents')`): DOWN → `[collex] veritabanı: ÇALIŞMIYOR —
ColleX-Baslat.cmd ile başlatın (…)` exit 1; MISSING db/schema → Turkish
`--ensure-db` hint, continues. (2) HTTP binds FIRST; `EADDRINUSE` →
`[collex] HATA: 8787 portu kullanımda — … ColleX-Durdur.cmd …` exit 1.
(3) `--with-mcp`: the token is generated in serve.mjs and passed to
`serve-mcp.mjs --token … --parent-stdin`; a stale listener on the MCP port is
reported in Turkish and the next free port (up to +20) is used; the child
starts in the BACKGROUND, `mcpState` goes `starting → ok → down` (a dead child
no longer kills the API — Turkish notice, typed 502 for /v1/research). (4)
`var/collex.pid` (node) and `var/collex-mcp.pid` (uvicorn pid from the ready
line) written; removed on clean shutdown (a hard kill on Windows cannot run
exit hooks — the files are overwritten at the next start and
ColleX-Durdur.cmd deletes them).

`serve-mcp.mjs` — child env adds `COLLEX_NO_DOTENV=1`, `LOG_LEVEL=WARNING`;
ready line `{"port","token","pid"}`; `--parent-stdin` watchdog: when the
parent's stdin pipe closes, uvicorn is shut down (verified: hard-killing
serve.mjs left no listener on 8899 and the uvicorn pid was gone).

`demo.mjs` — refuses to drop `collex_demo` when `legal.documents` has
`scope='tenant' and source='UPLOAD'` rows (exit 3, prints the
`intake.cli --list/--delete` hint) unless `--force-drop-uploads`.

`ColleX-Baslat.cmd` — if `/v1/health` already answers 200 on 8787: only opens
the browser; else kills stale `ColleX Sunucu` windows, keeps the PG start +
ensure-db logic, starts the server window, POLLS `/v1/health` (PowerShell
`Invoke-WebRequest`, 2 s × 30 = 60 s) and opens the browser only on 200;
prints what to look at on failure. `chcp 65001` kept.
`ColleX-Durdur.cmd` — window → pid files → netstat pids on 8898 and 8787 →
PG stop.

## 5. Known gaps / honesty notes

- Until integration passes `mcpState` into `createApp`, `/v1/research/health.state` reads `down` (derived) while the child is still starting; the sync/async research routes already behave correctly (typed 502 until ready).
- `research/health` `state` is additive but the two health tests that used `toEqual` on the body (research/routes, integration/app) were updated to include it.
- The per-page PDF gate keeps `PDF_MIN_CHARS_PER_PAGE = 10`: a scan whose every page carries a real text header (≥ 10 chars) still passes with only the headers indexed — documented in `intake/extract.py`, not fixed (OCR is out of scope).
- pid files survive a HARD kill on Windows (no exit hooks); serve.mjs overwrites them, ColleX-Durdur.cmd deletes them. A stale `var/collex.pid` is therefore not proof of a running server — the launcher uses `/v1/health`, never the pid file.
- The async registry is in-memory: a finished run's `result` is reachable through the answer store (persisted by integration's `PgAnswerStore`), the progress feed is not (30 min TTL).
- `ColleX-Baslat.cmd`'s `:health` line (the exact `for /f "usebackq"` + PowerShell probe) was exercised from a scratch copy on port 8819: `HEALTHY=0` with nothing listening, `HEALTHY=1` with `serve.mjs` up. The full double-click flow (PG start from cold → server window → browser) and `ColleX-Durdur.cmd` were reviewed by hand but NOT re-run end-to-end in this lane.
- `mevzuat_client.py` still loads `.env` at import (outside every lane's ownership) — listed in §3.5.
