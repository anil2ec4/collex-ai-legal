### Revision (`control-plane/src/drafting/revise.ts`, contract [D])

```ts
export interface DraftPatchParagraph { id?: string; text: string; evidenceIds?: string[]; role?: string; binding?: DraftBinding }
export interface DraftPatchSection { id: string; paragraphs: DraftPatchParagraph[] }
export interface DraftPatch { sections: DraftPatchSection[]; evidenceUse?: Record<string, boolean>; note?: string }
export function reviseDraft(draft: Draft, patch: DraftPatch, opts: { trustEntailment: boolean; now: () => Date }):
  { draft: Draft; issues: { path: string; message: string }[] }
```
Throws `DraftValidationError` (HTTP 400) for: unknown section id, duplicate section, template order violated. Soft issues (draft still produced, reported in `issues` and as `Düzenleme uyarısı:` warnings): empty paragraph skipped, unknown paragraph id → new id `p-<section>-u<n>`, invalid role, evidence id not in `evidence ∪ unusedEvidence`, lexical binding failing `evidenceOverlaps` (words AND numbers), entailment binding without `trustEntailment` (paragraph → KAYNAKSIZ), invalid entailment score/judge, **karşıt evidence under `hukuki-sebepler` or a legal role**, UPLOAD entry under a legal role, `evidenceUse` on karşıt/upload/unknown, `evidenceUse:false` on an entry other paragraphs still cite (line removed, entry kept). The karşı içtihat section cannot vanish by omission (kept + issue; send it with `paragraphs: []` to drop it). `ek-dogrulama` is regenerated (client content ignored + issue). Non-legal roles may cite any evidence (a fact paragraph may quote the contrary decision). Accepted entailment bindings are stored on the paragraph and logged in `machineWarnings`. Lane E calls this with `trustEntailment: true`.

### HTTP (`control-plane/src/drafting/routes.ts`)

- `POST /v1/drafts` — body pre-normalized (`normalizeDraftRequestInput`), zod with Turkish messages: parties `tckn` (`^\d{11}$`), `vkn` (`^\d{10}$`), `adres`, `vekil`; matter `mahkeme, esasNo, davaDegeri, arabuluculuk{yapildi: boolean|"evet"/"hayır", tarih, sonuc}, vekil, matterId (string|null), tarih`. `evidence.runId` triggers `await answers.warm?.(runId)`. Response `Draft` (version 1, `matterId` when given).
- `GET /v1/drafts?matterId=&limit=` → `{ drafts: DraftSummary[] }` (400 when `limit` ∉ 1..500; `[]` when the store has no `list`).
- `GET /v1/drafts/{id}` → latest version (after `store.warm?.(id)`), 404 `NOT_FOUND`.
- `PUT /v1/drafts/{id}` — body `DraftPatch` (zod: ≤40 sections, ≤400 paragraphs, text ≤20 000, ≤50 evidenceIds, binding union). `reviseDraft(..., { trustEntailment: false, now })`, `store.put`, **200 `{ ...Draft, issues: [...] }`** (`issues` is an additive top-level field of the response, not of the stored draft). 400 `INVALID_REQUEST` with labeled issues for structural errors/bad body; 404 for unknown id.
- `GET /v1/drafts/{id}/versions` → `{ versions: DraftSummary[] }` ascending; 404 for unknown id.
- `GET /v1/drafts/{id}/export?format=md|docx|udf` — `udf` runs `export.cli --format dilekce-udf`, replies `application/octet-stream`, `content-disposition: attachment; filename="<id>.udf"`, header **`X-ColleX-Experimental: udf`**; 400 message for a bad format names udf as `deneysel — UYAP Doküman Editörü'nde açarak doğrulayın`; exporter failures 500 `EXPORT_REFUSED` (exit 2) / `EXPORT_FAILED` with `note` = the same sentence for udf. `DraftDocxExecRequest` gains `timeoutMs` (60 000; the default runner passes it to `execFile`). Exports: `EXPORT_TIMEOUT_MS`, `UDF_EXPERIMENTAL_NOTE`, `draftPatchSchema`.

## Known gaps / honesty

- **UDF is deneysel.** The `content.xml` shape was taken from public UDF samples and the repo's own fixture; it was verified to round-trip through `intake/extract.py` and through this writer's read-back, **not** opened in the UYAP Doküman Editörü. Page/paragraph attributes (`pageFormat`, `Alignment`, `SpaceBelow`) are best guesses; the file is unsigned by design.
- `draft.evidence` keeps one entry **per uploaded chunk** (the closure set needs their ids); the DAYANAK KAYNAKLARI appendix therefore lists each chunk as its own `[K-n]` entry (compact, no quote block). The ek-dogrulama section groups uploads per file.
- Sebepler text matching: a law mentioned without any article in the matter text pulls in every article of that law; "TBK m. 344" pairs law+article only when the parser's spans are adjacent (≤4 chars). Bare dockets are matched by a `\d{4}/\d{1,6}` scan.
- The dative suffix for `matter.mahkeme` (`'NE`/`'NA`) is a last-vowel heuristic; the başlık line is reviewable text.
- `PUT` returns `issues` as an additive field on the response object only; the stored draft records them as `Düzenleme uyarısı:` warnings.
- `InMemoryDraftStore` capacity counts draftIds, not versions; a draft with many versions holds them all until evicted.
- The console form kinds, openapi paths and the `app.test.ts` count are integration work (above); no HTML/openapi/server file was touched.
- Fixture content in all tests is SENTETİK; nothing here measures legal quality.
