# 1. Fixture-corpus functional baseline (MEASURED)

## 1.1 What these numbers ARE

A **functional regression baseline**. `evals/fixtures/corpus/` contains eight
synthetic documents — a two-version TCK 5237 excerpt, a TBK 6098 excerpt, a
synthetic torba kanun (7999) that amends both, a deliberately contradictory pair
of Yargıtay decisions, a KVKK decision, and one tenant-scoped dilekçe used as
retrieval noise and as a cross-tenant tripwire. Every file is labelled
`SENTETİK TEST VERİSİ` in its own `_meta.notice`.

Because we authored both the documents and the questions, `expected_documents`
and `required_claims` in `fixture_corpus_gold.jsonl` are ground truth **by
construction** — no lawyer judgement is involved or claimed. That makes the set
scorable *today*, and makes a change in any number below a signal that
**something in the pipeline changed**, e.g.:

- exact reference resolution stopped pinning `TCK m.157` at rank 1;
- the `TCK` ↔ `5237 sayılı Türk Ceza Kanunu` parity regressed;
- an as-of query started returning the post-amendment text for a pre-amendment date;
- a citation stopped resolving, or its quote stopped hashing to its offsets.

## 1.2 What these numbers are NOT

- **Not** a Turkish legal quality benchmark. Recall over 7 logical documents is
  arithmetic, not evidence about Turkish law.
- **Not** an embedding/hybrid retrieval result. pgvector cannot be installed on
  the scratch PostgreSQL, so migrations `080000`/`090000` are never applied and
  the dense lane is a `NoopDenseLane`. This is a **lexical + exact-pin**
  baseline.
- **Not** an answer-quality measurement. Nothing generates an answer in this
  path; `required_claims` are carried in the gold set but **not scored**.
- **Not** a substitute for §2. The lawyer-annotated gold set and the labeling
  protocol in `evals/datasets/SCHEMA.md` remain the only route to a quality
  claim, and they remain **pending**.

## 1.3 Reproduce

```bash
# Windows (repo venv interpreter, as CLAUDE.md requires)
.venv/Scripts/python.exe scripts/run_evals.py

# POSIX
.venv/bin/python scripts/run_evals.py
```

Preconditions: a local scratch PostgreSQL reachable at
`127.0.0.1:55432` (user `postgres`, no password), `psycopg` installed in the
venv, Node ≥ 22 on `PATH`, and `npm ci` already run inside `control-plane/`
(the script bundles the TypeScript driver with the esbuild that ships in
control-plane's lockfile; it never installs anything).

Useful flags: `--fixture-only` (DB-free invariant subset), `--skip-ingest`
(re-measure an already-ingested database), `--keep-raw`, `--reports-dir`,
`--skip-report`.

The command creates and drops exactly one database, `collex_eval_test`, and
refuses any other name. It makes no network call except to that loopback
PostgreSQL.

## 1.4 Which layer was measured (no shortcuts)

The driver `evals/retrieval/measure_retrieval.ts` calls the **same functions the
product calls**:

```
searchLegalCorpus()            control-plane/src/retrieval/searchService.ts
  -> searchPipeline()          control-plane/src/retrieval/hybrid.ts
       normalizeTurkishSearch -> parseReferences -> exact-pin lane
       -> lexical ('turkish' FTS) lane -> pg_trgm lane -> RRF fusion
       -> per-document diversity cap
  -> exactPinLookup / lexicalSearch / trigramSearch
                               control-plane/src/store/chunkStore.ts  (real SQL)
buildEvidencePack()            control-plane/src/answer/evidencePack.ts
  -> validateEvidence          control-plane/src/verification/validator.ts
```

It is deliberately **not** the HTTP `POST /v1/search` route: that route is still
a scaffold that proxies the Deep-Research `search` MCP tool at an upstream
provider and never reads the local corpus, so measuring it would have measured
something other than corpus retrieval.

Retrieval returns database UUIDs, which change on every ingest. The harness
joins them back to stable unit ids
(`<external_id>@<version_label>#<structural path>`, e.g.
`kanun-5237@v2-20260115-7999#madde-157/fikra-1`) **after** retrieval has
returned. That join never reorders, filters or augments the ranking. See
`evals/datasets/FIXTURE_CORPUS_GOLD.md` §2.

These are enforced **by code**, not by prose: `scripts/run_evals.py` exits 1 if
any of them fails. Proven, not asserted:

- unit tests in `evals/tests/test_gates.py` flip every gate to FAIL with a
  payload carrying exactly that defect (tampered quote hash, quote that does not
  match its offsets, drifted document hash, rejected citation, unknown document,
  chunk id outside the inventory, evidence for an unknown version, a
  tenant-scoped hit, a totally failed lane, a dropped query);
- end to end: corrupting one version's stored `content_sha256` in
  `collex_eval_test` and re-running with `--skip-ingest` produced
  `RESULT: FAIL (quote_hash_integrity == 100%)` and **exit code 1**
  (26 → 17 verified, 9 stored-hash mismatches).

Note on the hash gate: `buildEvidencePack` recomputes `contentSha256` from the
text it just fetched, so text and hash always agree with *each other*. The
harness therefore also compares each evidence record's `contentSha256` against
the hash **ingestion stored** for that version — that comparison is what
actually detects canonical text drifting after ingest, and it is what the
end-to-end proof above trips.

## 1.6 What this run actually revealed (read before quoting any number)

1. **The lexical (`turkish` FTS) lane contributed ZERO hits across all 25
   queries.** `websearch_to_tsquery` AND-joins every term, so a natural-language
   question ("… hangi suçu oluşturur?") only matches a chunk containing *all* of
   its terms, which essentially never happens. The lane is not broken —
   `search_tsv_tr @@ websearch_to_tsquery('turkish','dolandırıcılık')` matches 10
   chunks — but on full questions its recall is 0. **All recall in this run came
   from the exact-pin lane (36 hits) and pg_trgm (5 hits).** Any "Recall@k" here
   is essentially "did the query contain a parseable citation".
2. **Contrary-authority recall is 0.0.** No query surfaced the opposing Yargıtay
   decision. The contrary/fact-pattern queries carry no citation, so the exact-pin
   lane cannot fire and (per finding 1) the lexical lane returns nothing.
   `control-plane/src/planner/contrary.ts` exists but is not part of this
   retrieval path.
3. **Abstention precision is 57.1%, not because the system abstains wrongly on
   purpose, but because "zero hits" is what a failed lexical lane looks like.**
   Three queries with real answers in the corpus (`fx-fact-002`,
   `fx-amend-003`, `fx-contrary-001`) returned nothing. Abstention recall is
   100% only because *every* hard query also returns nothing.
4. **Amendment-target resolution is partial.** `fx-amend-001` retrieves the
   amending provision (7999 m.1) but not its target (TCK m.157 v2);
   `fx-amend-003` (no citation in the query) retrieves nothing. The
   `document_relations` resolver is not wired into retrieval yet.
5. **Exact reference and abbreviation parity are clean.** 9/9 exact references
   at rank 1, and all 4 parity pairs produced byte-identical top-10 rankings —
   `TCK m. 157` and `5237 sayılı Türk Ceza Kanunu m. 157` behave the same.
   Full-name accuracy (71.4%) is *lower* than abbreviation accuracy (100%) only
   because the two amendment queries happen to be full-name form; it is not an
   abbreviation-handling defect.
6. **Temporal versioning works where a citation exists.** All three `temporal`
   queries picked the correct version, including the 2026-01-10 edge (one day
   before the amendment commences).

None of the above was tuned away. The gold queries are ordinary Turkish
questions and were not rewritten to make the lexical lane look better.

# 2. Legal quality benchmark (STILL DOES NOT EXIST)

Everything in this section is unchanged and still **pending**. A legal quality
number requires all of it.

## 2.1 What is NOT the benchmark

`scripts/embedding_quality_check.py` is a **4-query Turkish sanity check** for
the configured embedder (muris muvazaası, kıdem tazminatı, KDV indirimi, imar
iptali). It verifies the embedder ranks each query's matching document first. It
is a smoke signal that the embedding wiring works — it is **not** a gold set and
**not** a benchmark. Per the brief (§8.1), a model decision requires at least
250–400 lawyer-labeled queries; four hand-written pairs cannot stand in for that.
Never report its 4/4 as a retrieval score.

`legal_gold_v1.seed.jsonl` is likewise **not** scorable: 40 unvalidated engineer
drafts (`adjudication_status: pending`, `annotators: []`). Any metric computed on
the seeds is a plumbing check of the harness, not a result.

§1 of this file is **also** not the benchmark. It is synthetic data.

## 2.2 Preconditions before a real benchmark can be produced

1. **Gold set adjudicated.** The seed drafts have gone through the labeling
   protocol in `evals/datasets/SCHEMA.md` (two lawyers, blind A/B, adjudication,
   IAA reported) and been promoted to `legal_gold_v1.jsonl`, all records
   `complete`.
2. **Canonical corpus + ids.** Every `expected_documents` / `contrary_authorities`
   id resolves to a real canonical document in the store (brief §5 registry).
3. **Live embedding + index.** A chosen embedding model (brief §8.2 bake-off:
   BGE-M3 1024 self-host, voyage-4 1024, text-embedding-3-large 1024) has
   embedded the corpus into a pgvector index — which also means migrations
   `080000`/`090000` are applied somewhere they can run.
4. **A lexical lane that survives natural-language questions.** Finding 1 in
   §1.6 must be addressed (OR-semantics / `plainto_tsquery` fallback / query
   term selection / a real dense lane) before any retrieval comparison is
   meaningful; otherwise the benchmark measures citation parsing.
5. **Train/tune vs blind-test split fixed**, blind-test untouched during tuning,
   temporal holdout scored separately.

## 2.3 Procedure

Pre-flight, then produce a results JSONL from the live retriever, then score:

```bash
.venv/Scripts/python.exe -m pytest evals/tests -q          # harness self-tests
.venv/Scripts/python.exe scripts/embedding_quality_check.py # embedder sanity, NOT a score

.venv/Scripts/python.exe evals/retrieval/benchmark.py \
  --gold evals/datasets/legal_gold_v1.jsonl \
  --results <results>.jsonl \
  --out evals/reports/baseline_<model>_<YYYY-MM-DD>.json \
  --k 5 10 20
```

Each results line: `{"id": "<gold id>", "ranked_document_ids": [...],
"latency_ms": 123.4}`; abstentions emit `"ranked_document_ids": []` and
`"abstained": true`. Watch `counts.missing_results` — nonzero means the runner
dropped queries and the numbers are not comparable.

## 2.5 Reporting rules

- Report the blind-test split and the temporal holdout separately; never average
  them into one headline number.
- Report inter-annotator agreement alongside the metrics.
- State the embedding/reranker/index configuration next to every number (§8.2).
- Record the real command and its exit code. A failed or partial run is reported
  as such, not silently dropped (§13.2).
- Never present a §1 number as a §2 number, and never present synthetic fixture
  content as real Turkish case law.
